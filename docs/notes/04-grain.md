# 04 颗粒：每像素哈希噪声，24 帧跳变

本文讲的算法移植自原作场景，这里解释的是本仓库对它的实现。

## 画面上是什么

整个画面上蒙着一层极细的、不停闪动的噪点，像胶片的颗粒。它很淡，最亮的一点最多比底下的颜色亮约 9 个色阶（满分 255），但它让大块的渐变背景有了质感，也盖掉了低分辨率背景可能带来的色带。

颗粒是最后一个画的层，盖在背景、卡片和倒影之上。

## 术语

- **全屏通道（full-screen pass）**：画一个盖住整个视口的图形，让片元着色器对每个像素都跑一遍。`FullscreenPass` 用的是一个超大的三角形，顶点是 `(-1,-1)`、`(3,-1)`、`(-1,3)`，超出屏幕的部分会被裁掉，比两个三角形拼成的矩形少一条对角线。
- **预乘 alpha**：输出的颜色已经乘过透明度，混合时不再乘。详见 [03 卡片](03-cards.md)。

## 第一步：每个像素一个随机数

```glsl
// src/gl/shaders/grain.frag.glsl
vec2 pos = vec2(gl_FragCoord.x, uRes.y - gl_FragCoord.y);
float g = (ph((pos + vec2((frame * 13.7), (frame * 7.3)))) - 0.5);
```

`pos` 是这个像素在绘图缓冲里的坐标，原点在左上角（和别的着色器一样，翻转一下 y）。`ph` 就是 [01 印花](01-print.md) 里讲过的哈希：同样的输入给同样的输出，输出在 0 到 1 之间看起来是乱的。

和印花不同，这里不做插值。相邻像素各取各的哈希值，所以相邻像素之间完全没有关联，这是"白噪声"。印花里的值噪声则是平滑的。

减去 0.5 之后，`g` 的范围是 -0.5 到 0.5，正负各占一半。

## 第二步：24 帧量化

```glsl
float frame = floor((uTime * 24.0));
```

`uTime` 是场景时间（秒），乘 24 再向下取整，得到一个每 1/24 秒加一的整数 `frame`。在同一个 `frame` 值持续的那 1/24 秒里，同一个像素的 `pos + (frame × 13.7, frame × 7.3)` 不变，所以哈希值也不变。只有当 `frame` 加一时，查表位置才整体平移 `(13.7, 7.3)`，所有像素同时换一批新的随机数。

这样的好处是颗粒像真胶片一样每秒跳 24 次，而不是每帧都在变。屏幕刷新 60 次每秒时，每个 `frame` 值会持续 2 到 3 帧：

| 屏幕帧（60 fps） | `uTime` | `frame` |
| ---------------- | ------- | ------- |
| 0                | 0       | 0       |
| 1                | 0.0167  | 0       |
| 2                | 0.0333  | 0       |
| 3                | 0.05    | 1       |
| 4                | 0.0667  | 1       |
| 5                | 0.0833  | 2       |

`uTime` 传的是 `s.time`（见 `SceneRenderer.render` 里 `this.grain.render(r, s.time, ...)`），它在 `advance` 里累加，每帧最多加 `maxDt = 0.05` 秒。

偏移量 `(13.7, 7.3)` 是从原作照抄的常数。以 `frame = 24`（即 `uTime = 1` 秒）为例，所有像素的查表位置被偏移 `(328.8, 175.2)`；到 `frame = 25` 偏移变成 `(342.5, 182.5)`，又是全新的一批随机数。

## 第三步：用一次预乘混合同时实现提亮和压暗

先把随机数拆成两个非负的量：

```glsl
float lift = (max(g, 0.0) * uGrain);
float drop = (max(-(g), 0.0) * uGrain);
fragColor = vec4(vec3(lift), (lift + drop));
```

`g` 是正的时候只有 `lift` 有值，负的时候只有 `drop` 有值，两者不会同时非零。`uGrain` 是强度 `SCENE.grain`，默认 0.07，所以 `lift` 和 `drop` 的最大值都是 `0.5 × 0.07 = 0.035`。

输出的是 `vec4(lift, lift, lift, lift + drop)`，这是预乘 alpha：颜色是 `lift`，透明度是 `lift + drop`。混合方式是源因子 One、目标因子 OneMinusSrcAlpha（`GrainPass` 构造函数里调用 `setPremultipliedBlending`），所以结果是：

```
结果 = 输出色 + 底下的颜色 × (1 - 输出 alpha)
     = lift + 底色 × (1 - lift - drop)
```

分两种情况看：

- `g > 0`（`drop = 0`）：结果 `= lift + 底色 × (1 - lift)`，即把底色向白色 1 混合，混合比例是 `lift`。相当于叠一层白色，透明度 `lift`。
- `g < 0`（`lift = 0`）：结果 `= 底色 × (1 - drop)`，即向黑色 0 混合，比例 `drop`。相当于叠一层黑色，透明度 `drop`。

一次绘制、一个混合公式，就同时做到了有的像素提亮、有的像素压暗。不需要先读底色再自己算。

数值例：某处底色 0.5，`uGrain = 0.07`。

| `ph` 的输出 | `g`  | `lift` | `drop` | 结果                           |
| ----------- | ---- | ------ | ------ | ------------------------------ |
| 0.8         | 0.3  | 0.021  | 0      | `0.021 + 0.5 × 0.979 = 0.5105` |
| 0.2         | -0.3 | 0      | 0.021  | `0.5 × 0.979 = 0.4895`         |
| 0.5         | 0    | 0      | 0      | 0.5，不变                      |

最大的偏移是 `0.035 × (1 - 0.5) = 0.0175`（底色 0.5 时），整个范围里最多 `0.035`，乘 255 约 9 个色阶。平均偏移 `|g|` 是 0.25，乘 `uGrain` 约 0.0175，约 4.5 个色阶。

两个端点值得想一想：底色是纯黑 0 时，`drop` 不起作用，只有 `lift` 能提亮；底色是纯白 1 时，反过来，`lift` 不起作用，只有 `drop` 能压暗。所以颗粒不会把颜色推出 0 到 1 的范围。

## 颗粒的大小

颗粒的格子是绘图缓冲的一个像素。绘图缓冲固定是 1280×720（`renderBufferSize`），由浏览器放大到窗口尺寸。窗口 1920×1080 时，一个颗粒就是 1.5 个屏幕像素，会略有模糊。它不随窗口大小变化，这和原作按画板分辨率渲染再缩放的做法一致。

如果把 `SCENE.renderScale` 改成 2，缓冲变成 2560×1440，颗粒变得更细，但注意它同时会改变所有层的分辨率，原作并不这样做。

## 自己动手试试

改 `src/config/scene.ts` 里的 `grain: 0.07`，改成 `grain: 0.5`。

保存后整个画面蒙上很重的噪点，每秒闪 24 次。每个像素最多偏移 0.25（约 64 个色阶）：暗处能看到明显的亮点，亮处能看到明显的暗点。改成 `0` 则颗粒完全消失，画面变得干净，但也更平。

撤销：改回 `0.07`，或者执行 `git checkout src/config/scene.ts`。
