# 01 印花：一张纯靠公式画出来的图案

本文讲的算法移植自原作场景，这里解释的是本仓库对它的实现。

## 画面上是什么

每张卡片上的图案、背景里那团流动的色彩，用的都是同一类图：一张 640×400 的"印花"，像一块印染布。它没有任何图片文件，每个像素的颜色都由一段着色器（shader，在 GPU 上对每个像素各跑一遍的小程序）算出来。

十个应用各有一张。它们长得不同，是因为 `src/config/content.ts` 里每个应用有四个颜色、一种图案类型 `kind`、一个种子 `seed`、一个图案密度 `scale` 和一个墨渍强度 `ink`。着色器本身只有一份。

可以先看一眼全部十张：开发服务器打开 `/?debug=prints`，画布会按应用顺序排出十张印花（见 `src/gl/SceneRenderer.ts` 的 `drawPrintGrid`）。

## 对应的源码

| 文件                             | 作用                                               |
| -------------------------------- | -------------------------------------------------- |
| `src/gl/shaders/common.glsl`     | 哈希 `ph`、值噪声 `pnoise`、分形噪声 `fbm`         |
| `src/gl/shaders/print.frag.glsl` | 印花的片元着色器，含五种图案的 `pattern_mask`      |
| `src/gl/prints.ts`               | `createPrints`：给每个应用建一张渲染目标并渲染一次 |
| `src/config/content.ts`          | 每个应用的颜色、`kind`、`seed`、`scale`、`ink`     |

## 术语先说清

- **片元着色器（fragment shader）**：对目标图像的每个像素运行一次，输入是这个像素的位置，输出是颜色。
- **渲染目标（render target）**：不画到屏幕、而是画进一张纹理里。画完以后这张纹理可以当图片给别的着色器采样。本项目里印花、背景都先画进渲染目标。
- **值噪声（value noise）**：给整数网格点各分配一个随机数，格子内部用平滑插值得到连续变化的随机场。
- **fbm（fractal Brownian motion，分形布朗运动）**：把不同频率的噪声叠在一起，高频的幅度逐级减半，得到有大块也有细节的自然纹理。

## 第一步：哈希，把坐标变成"随机数"

GPU 上没有 `random()`。常用办法是哈希（hash）：同一个输入永远给同一个输出，但输出看起来是乱的。

```glsl
// src/gl/shaders/common.glsl
float ph(vec2 p) {
  float h = dot(p, vec2(127.1, 311.7));
  return fract(sin(h) * 43758.547);
}
```

`dot` 把二维坐标压成一个数，`sin` 把它变成 -1 到 1 的振荡值，乘一个大数 43758.547 把小数部分放大成乱序，`fract` 取小数部分，得到 0 到 1。

几个实际值（按 64 位浮点算，GPU 上用 32 位，末几位会有出入）：

| 输入   | `ph` 的输出 |
| ------ | ----------- |
| (0, 0) | 0           |
| (1, 0) | 约 0.327    |
| (0, 1) | 约 0.818    |
| (1, 1) | 约 0.103    |

## 第二步：值噪声，在随机点之间平滑过渡

```glsl
// src/gl/shaders/common.glsl
vec2 i = floor(p);
vec2 f = fract(p);
vec2 s = (f * f) * (vec2(3.0) - (2.0 * f));
```

`floor(p)` 是所在格子的左下角，`fract(p)` 是格内位置 `f`。四个角各取一个哈希值 `a b c d`，然后先沿 x 混合、再沿 y 混合。

不直接用 `f` 做混合比例，而是先过 `f*f*(3-2f)`（smoothstep 曲线），这样格子边界处的斜率是 0，相邻格子之间没有折痕。

一个算例：`p = (0.25, 0.5)`，落在格子 (0, 0) 里。`s.x = 0.25² × (3 − 0.5) = 0.15625`，`s.y = 0.5² × (3 − 1) = 0.5`。用上表四个角的值：

- 下边：`mix(0, 0.327, 0.15625) ≈ 0.051`
- 上边：`mix(0.818, 0.103, 0.15625) ≈ 0.706`
- 沿 y 混合：`mix(0.051, 0.706, 0.5) ≈ 0.379`

## 第三步：fbm，叠五层

```glsl
// src/gl/shaders/common.glsl
float fbm(vec2 p, int octaves) {
  float v = 0.0;
  float a = 0.5;
  vec2 q = p;
  for (int i = 0; i < octaves; i++) {
    v = v + (a * pnoise(q));
    q = (q * 2.07) + vec2(13.0, 7.0);
    a = a * 0.5;
  }
  return v;
}
```

每一层（octave）的坐标放大 2.07 倍，幅度减半。频率乘 2.07 而不是 2，并且每层加偏移 `(13, 7)`，是为了让各层的格点不重合，避免出现规则的网格痕迹。

5 层的幅度和是 0.5 + 0.25 + 0.125 + 0.0625 + 0.03125 = 0.96875，所以 `fbm(..., 5)` 的取值范围是 0 到 0.96875，多数时候在 0.5 上下。背景着色器用 3 层（最大 0.875），同一个函数，传参不同。

## 第四步：用两个阈值把标量场切成三块色域

先算一个标量场 `region`：

```glsl
// src/gl/shaders/print.frag.glsl
float region = (n0 + (0.22 * sin((q.y * 3.5) + (n1 * 6.0)))) + (0.12 * sin((q.x * 2.2) + seed));
```

`n0`、`n1` 是两个不同频率的 fbm。加上的两个正弦项让等值线带点波浪方向感，不然纯噪声的块看起来太均匀。

然后用两个很窄的 `smoothstep` 当阈值：

```glsl
float mA = smoothstep(0.4, 0.45, region);
float mB = smoothstep(0.6, 0.65, region);
col = mix(col, uC1, mA);
col = mix(col, uC2, mB);
```

`smoothstep(0.4, 0.45, x)` 在 x 小于 0.4 时为 0，大于 0.45 时为 1，中间是平滑过渡。过渡区只有 0.05 宽，所以几乎是硬边。结果：

| `region`    | `mA` | `mB` | 颜色                         |
| ----------- | ---- | ---- | ---------------------------- |
| 小于 0.4    | 0    | 0    | `uC0`，底色                  |
| 0.45 到 0.6 | 1    | 0    | `uC1`，中间色                |
| 大于 0.65   | 1    | 1    | `uC2`，高亮色                |
| 0.425       | 0.5  | 0    | 底色和中间色各一半（边界上） |

## 第五步：图案叠在色域上

`q * uPP.z` 把坐标乘上 `scale`，再取 `fract` 就是在每个格子里重复同一个图形。`uPP` 是一个 `vec4`，装着 `(kind, seed, scale, ink)`。

`pattern_mask(kind, q, density)` 返回 0 到 1 的遮罩，1 表示这里画图案色。五种图案各是一个距离函数：

| `kind` | 图案 | 怎么算                                                                                          |
| ------ | ---- | ----------------------------------------------------------------------------------------------- |
| 0      | 圆点 | 到格子中心的距离 `length(cell)` 小于半径 `r`，边缘 `smoothstep` 柔化 0.04                       |
| 1      | 加号 | 两条细长条取并集：宽 0.06 的横条和竖条，臂长是 `r`                                              |
| 2      | 鳞片 | 奇数行横向错开半格；到格子底边中点的距离 `d` 落在 0.3 到 0.5 之间，得到一圈弧，层层叠起来像鱼鳞 |
| 3      | 竖条 | `step(fract(q.x * 0.5), 0.25 + 0.35 * density)`，周期是两个格子                                 |
| 4      | 方块 | 切比雪夫距离 `max(abs(cell.x), abs(cell.y))` 小于 `r`                                           |

其中 `r = 0.12 + 0.3 * density`。`density` 是第三个 fbm（坐标另加偏移 `(9, 4)`），所以点和加号的大小在画面上是慢慢变化的，不是整齐划一。

主图案只画在中间色域里，不画进高亮色域：

```glsl
float inA = mA * (1.0 - mB);
col = mix(col, uC3, (pat * inA) * 0.9);
```

高亮色域里画的是"互补"的图案：`pattern_mask(4.0 - uPP.x, ...)`。互补的配对是点和方块、加号和竖条、鳞片和自己。它更密（坐标再乘 1.7），颜色是底色 `uC0`，强度只有 0.35，作为一层很淡的暗纹。

## 第六步：墨渍和纸纹

墨渍是又一层 fbm 取阈值：

```glsl
float ink = smoothstep(0.64, 0.7, fbm((q * 1.5) + vec2(seed * 2.3, 9.0), 5));
col = mix(col, uC0 * 0.25, ink * uPP.w);
```

fbm 值超过 0.7 的地方才有墨渍，所以是零星的几块。颜色是底色压到 25%，强度乘 `ink`。`ink` 为 0 就完全没有墨渍，为 0.9 就压得很暗。

纸纹是一层高频噪声：

```glsl
col = col * (0.94 + (0.08 * pnoise(q * 90.0)));
```

系数在 0.94 到 1.02 之间。印花宽度对应 `q.x` 大约 0 到 3.52，乘 90 后横向约 317 个格子，落在 640 像素上，每格约 2 个像素，所以肉眼看是细腻的颗粒。

整个着色器共调用 21 次 `pnoise`：四个 fbm 各 5 层，加纸纹 1 次。每次 `pnoise` 有 4 次哈希，每次哈希一个 `sin`。

## 种子怎么决定形状

坐标先被平移：

```glsl
vec2 uv = vec2(p.x * (uRes.x / uRes.y), p.y) * 2.2;
vec2 q = uv + vec2(seed * 3.1, seed * 1.7);
```

这里 `p` 是 0 到 1 的像素位置，乘宽高比 1.6 保证格子是正方形，再放大 2.2 倍。噪声场在平面上是无限延伸的，`seed` 决定从哪里截取一块。`seed` 为 0.3 和 1.1 的两张印花，是同一个噪声场的两个不同位置。此外墨渍层有自己的偏移 `seed * 2.3`，`region` 里还有 `sin(q.x * 2.2 + seed)`，所以种子同时影响色域和墨渍。

四个颜色决定色调，`kind` 和 `scale` 决定图案，`ink` 决定墨渍。这五项都读自 `content.ts`，着色器里没有任何颜色字面量。

## 为什么只渲染一次

`createPrints` 在 `SceneRenderer` 构造时执行：

```ts
// src/gl/prints.ts
renderer.setRenderTarget(target);
pass.render(renderer);
```

它给每个应用建一个 640×400 的 `WebGLRenderTarget`，把四个颜色和 `uPP` 写进 uniform，画一帧，保存下来。之后每帧里背景和卡片只是把这十张纹理当图片采样，不再重新计算。

原因很直接：印花只取决于 `content.ts`，运行时不会变，而它每个像素要做 21 次噪声，值得缓存。每帧重算十张是浪费。

这十张纹理的寻址方式设为镜像重复（`THREE.MirroredRepeatWrapping`）。坐标超出 0 到 1 时不是回绕，而是折回：1.2 读到的是 0.8，2.0 读到的是 0。背景着色器会把采样点移出边界，镜像重复保证接缝处不跳变。

## 一个坐标细节

原作的片元坐标原点在左上角、y 向下，而 WebGL 的 `gl_FragCoord` 原点在左下角。所以着色器开头有一行：

```glsl
vec2 fragPos = vec2(gl_FragCoord.x, uRes.y - gl_FragCoord.y);
```

于是原作的第 0 行（顶部）落在渲染目标纹理的 v = 1 处。后面所有采样印花的地方都写 `texture(tex, vec2(uv.x, 1.0 - uv.y))`，把原作的 uv 翻回来。
