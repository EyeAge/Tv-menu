# TV Menu 网页复刻：设计文档

- 日期：2026-11-05
- 状态：复刻目标已确认为 TV Menu。印花"形状一致"按用户倾向暂定，见第 10 节。
- 仓库：`git@github.com:EyeAge/Tv-menu.git`（公开，默认分支 `main`）

## 1. 意图与缘由

用网页技术复刻 <https://gmgn.monster/> 的 "TV Menu" 场景。原作用 Rive CLI 制作：整页只有一个 canvas 和一个 `.riv` 场景文件，画面是一个电视首页菜单，有 10 张带程序化"印花"的 3D 卡片、随选中项变化的背景、键盘和鼠标导航。

这个站之前展示过一个机械蜻蜓场景，后来被站主换成了 TV Menu。蜻蜓版本找不回来，以后有素材时另开仓库做。

两个目的：

1. **练手**：React、three.js、GLSL 着色器、动效和交互状态机。
2. **作品集**：成品要拿得出手。

之后可能把内容换成别的主题，所以内容必须是配置驱动的。

全部代码由实现者写完。用户通过成品、代码和学习笔记来了解每个效果，这不是一个留练习给用户的教学项目。

**项目性质是移植。** 原作的着色器源码和脚本字节码都内嵌在公开的 `.riv` 文件里，可以完整读出。本项目把它们的算法和参数移植到 three.js 和 GLSL，文字层改用 DOM。README 必须如实写明这一点并注明原作。

成功的样子：1440×900 窗口下和原站并排，肉眼看不出明显差别；交互行为一致；推到 `main` 自动上线。

## 2. 目标、非目标、反目标

### 目标

1. **视觉还原**：背景、卡片、倒影、文字排版、颗粒，并排对比肉眼看不出明显差别。印花和背景的色块形状与原站一致。
2. **交互还原**：键盘和鼠标的全部行为与原站一致（见 4.5）。
3. **配置驱动**：应用列表、输入源、每张卡片的印花参数全部来自一个配置文件，换内容不改代码。
4. **流畅**：普通笔记本 1080p 下稳定 60fps，印花纹理只生成一次。
5. **学习笔记**：五篇中文说明，讲清每个效果的原理和参数。
6. **自动部署**：推 `main` 自动发布到 GitHub Pages。

### 非目标

- 像素级一致。不同显卡的浮点精度和字体渲染引擎不同，做不到。
- 移动端专门布局（和原站一样等比缩放留黑边）。
- 应用"打开"后的页面、后端、账号、真实视频源。
- 真 3D 模型、使用 Rive 运行时。
- 触摸手势、遥控器或手柄、音效、无障碍朗读优化、减少动效模式。
- 开源协议：暂不加 LICENSE，以后由用户决定。

### 反目标（即使能跑也算失败）

- 不注明来源。README 必须写明算法和参数移植自 gmgn.monster 的原作。
- 把原站的资源（`.riv`、原站截图、抽出的源码和反汇编）提交进公开仓库。
- 内容写死在组件或着色器里。
- 文字画在画布上导致发虚。
- 运行时依赖外部 CDN（字体、库都要打进产物）。

## 4. 复刻对象的完整描述

本节的行为和数值来自原作脚本的反汇编，并用实测截图核对过。**和原站实际行为有出入时以原站为准。** 故意偏离原站的地方只有第 5 节列出的那些。完整的伪代码在本地的 `.reference/extracted/scene-spec.md`。

### 4.1 舞台

- 逻辑舞台 1280×720。任何窗口尺寸下都等比缩放、居中，舞台外露出 `#07090c` 底色。
- 例：1440×900 的窗口里舞台是 1440×810，上下各留 45px。手机竖屏下舞台只是中间一条。

### 4.2 画面元素

文字的位置和字号由实现者从参考截图测量，这里只描述有什么。

- **左上**：时钟，格式 `h:mm`（12 小时制，无前导零，无 AM/PM），Inter。下面一行日期，`WEEKDAY, MONTH DD`（英文、全大写、日两位数），等宽小字加宽字距。取浏览器本地时间。
- **右上**：两行等宽小字，加宽字距。第一行是绿色圆点加 `SMARTCAST · VOL 44`，浅灰，**静态**。第二行是琥珀色的 `PRINT {印花名} · {配色名}`，随选中的应用变化；焦点在 Inputs 行时保持不变。
- **标题区**：
  - 计数：应用行 `APPS n / 10`，Inputs 行 `INPUTS n / 5`。琥珀色等宽小字。
  - 大标题：Lora 衬线体，白色。应用行显示应用名，Inputs 行显示输入源名。
  - 副标题：Inter。应用行显示应用副标题，Inputs 行重复输入源名。
  - 提示：`Press OK to open`，Inter，暗灰，静态。
- **应用行**：小标签 `APPS`，下面是卡片行。共 10 张，同时可见 5 张。卡片下方是应用名（Inter）。
- **Inputs 行**：小标签 `INPUTS`，下面 5 个圆角半透明方块，每个 150×50，左边距 60，间距 160，纵向位置 606 到 656。第一个方块的名字上方有一个极小的 `CAST` 标签。选中框是一圈明亮的白色描边加轻微外发光，只在焦点位于 Inputs 行时可见，会平滑滑到被选中的方块。
- **底部提示**：`ARROWS MOVE · OK OPENS · BACK GOES UP`，等宽极小字，暗灰。
- **全屏胶片颗粒**。

### 4.4 四个视觉效果

**a. 印花**

每个应用一张 640×400 的纹理，离屏渲染一次后复用，寻址方式是镜像重复。

1. 五层值噪声加两个正弦扰动，得到一个标量场。
2. 两个很窄的阈值把画面切成三块色域：底色、中间色、高亮色，边界近似硬边。
3. 中间色域里叠加图案色的重复图案。图案五种：圆点、加号、鳞片、竖条、方块。圆点和加号的大小被另一层噪声调制。
4. 高亮色域里叠加互补类型的图案，更密、更淡、用底色。
5. 另一层噪声做阈值，得到零星的墨渍斑块，颜色是压得很暗的底色。
6. 高频噪声做轻微的纸纹明暗。

**b. 背景**

背景渲染在四分之一分辨率的缓冲里，再用双线性放大铺满舞台。画面的柔和感有一部分来自这里。

1. 只取印花纹理中间约六成的区域。采样坐标被两层缓慢漂移的噪声扭曲，形成缓慢流动的褶皱。
2. 七抽头的简易模糊，过渡进行中半径加大。
3. 过渡：水平方向的斜坡加噪声构成遮罩，一个随进度推进的阈值把新旧两张图分开，方向由新旧应用的先后决定。阈值处叠一条暖白色混光晕色的亮带，过渡中段最亮。
4. 调色：部分去饱和，整体压暗一半，左侧和下半部再压暗。
5. 在选中卡片的位置叠一个光晕色的径向光斑。焦点在 Inputs 行时光斑强度降到 35%。
6. 暗角。

**c. 卡片**

- 透视相机：视场角 30 度，位于 z=6 看向原点。
- 每张卡片是一个 1×0.6×0.06 的盒体，侧面可见。相邻卡片中心间距 1.07。
- 正面贴印花纹理中间约六成的区域。边缘一圈窄的深色倒角。
- 一道斜向的白色高光带。卡片被选中时，以及在它上面按 OK 时，高光带从一侧扫到另一侧，约 0.9 秒扫完。
- 一个固定方向光，漫反射加一点高光。
- 选中程度是连续值：卡片越接近选中位置，越大（0.86 到 1.02 倍）、越靠前、描边越亮。
- 每张卡片绕竖轴的旋转角和它离屏幕中心的水平距离成正比，所以两侧的卡片朝中间偏。
- 倒影：每张卡片在地面线下方有一个镜像副本，压暗，透明度向下快速衰减，最强约三成。
- 绘制顺序：离选中项最远的先画，选中的最后画。先画全部倒影，再画全部本体。
- 焦点在 Inputs 行时，选中卡片保持放大和靠前，描边和提亮降到 45%。

**d. 颗粒**

每像素哈希噪声，以 24fps 跳变，强度 0.07。正值提亮，负值压暗。

**渲染分辨率**

整个 WebGL 层以固定的 1280×720 内部分辨率渲染，由浏览器放大到屏幕尺寸，不使用多重采样（抗锯齿关闭）。这一点是实施中通过测量确定的：原作按画板分辨率渲染再缩放，且没有多重采样。

### 4.5 交互行为

**键盘**（按下和长按重复都生效）

- 应用行：`←` `→` 移动选中项，两端钳制不循环；`↓` 进入 Inputs 行；`Enter` 让选中卡片的高光带重扫一次，背景不变；其他键无效果。
- Inputs 行：`←` `→` 移动，两端钳制；`↑`、`Esc`、`Backspace` 回到应用行，应用选中项不变；`↓` 和 `Enter` 无效果。
- Inputs 行的选中位置一直保留，再次进入时回到它。首次进入是第一个。
- 页面加载后自动获得键盘焦点。

**鼠标**

- 移到某张卡片上：选中该应用，焦点切到应用行。
- 移到某个输入源方块上：选中该输入源，焦点切到 Inputs 行。
- 点击当前已选中且焦点在应用行的卡片：高光带重扫一次。
- 点击其他卡片或方块：效果和移上去一样。
- 移到空白处、滚轮：无效果。
- 卡片的命中区域是它在屏幕上的投影矩形，随选中程度变化。

**卡片行滚动**

卡片行有一个 5 格宽的可见窗口，窗口位置是独立的状态：

- 选中项在窗口内：窗口不动。
- 选中项超出窗口右边：窗口右移，直到选中项落在最右一格。
- 选中项超出窗口左边：窗口左移，直到选中项落在最左一格。
- 窗口不在最左时，舞台左边缘会露出前一张卡片的一部分。

**卡片名标签**

- 共 6 个标签槽位，跟着卡片行滚动。
- 透明度随选中程度从 35% 到 100% 变化，靠近舞台两侧边缘时淡出。焦点在 Inputs 行时，标签自身的透明度乘 0.5，它所在的整组（APPS 标签和卡片名）再乘 0.45 的不透明度，和原作一致。

**时间**

- 选中项、Inputs 选中框是指数缓动，速率 9。卡片行滚动是指数缓动，速率 7。
- 每帧的时间步长上限是 0.05 秒。
- 背景过渡每次 1.1 秒。新的选中项进入一个先进先出的队列：当前过渡播完才取下一个，和当前画面相同的项直接跳过。

### 4.6 字体

原作内嵌三个字体，都是 OFL 协议的免费字体：Lora（大标题）、Inter（时钟、副标题、提示、卡片名、输入源名）、JetBrains Mono（所有全大写加宽字距的小字）。

## 11. 实施中的裁决

以下是实施过程中做出的决定，取代前文和计划中与之不一致的写法。

- 渲染分辨率固定为 1280×720，与窗口尺寸和设备像素比无关，由浏览器放大。
- 抗锯齿关闭。
- 原作写 `pow(x, 2.0)` 的地方，实现里用 `pow(abs(x), 2.0)`，因为 GLSL 对负底数的结果未定义。
- 卡片盒体按原作的面顺序和绕向重建。
- 因字体光栅化不同，某些缩放下的小号等宽文字会比原作略暗。
- `CAST` 标签的字距用 0.7 px。
- 焦点在 Inputs 行时，卡片名标签的透明度乘 0.5，整组（APPS 标签和卡片名）再乘 0.45，和原作一致（4.5 节原写"再减半"）。
- （裁决 13）舞台矩形 `0..stageW × 0..stageH` 以外的指针位置不命中任何东西，边界上的点算在舞台内。所以两侧黑边不会选中伸出舞台边缘的卡片。
- WebGL 上下文丢失后靠重建渲染器恢复：丢失时释放渲染器，恢复时新建一个，因为所有 GPU 资源（包括启动时只画一次的印花纹理）都随上下文一起丢了。
