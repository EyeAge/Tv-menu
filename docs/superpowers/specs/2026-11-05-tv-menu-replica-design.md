# TV Menu 网页复刻：设计文档

- 日期：2026-11-05
- 状态：草稿，待确认。**复刻目标本身也待确认**：gmgn.monster 的内容更换过，本文描述的是 2026-11-04 到 11-05 实测到的 TV Menu 版本。
- 仓库：`git@github.com:EyeAge/Tv-menu.git`（公开，默认分支 `main`）

## 1. 意图与缘由

用网页技术手写复刻 <https://gmgn.monster/> 的 "TV Menu" 场景。原作是用 Rive CLI 做的：整页只有一个 canvas 和一个 `.riv` 场景文件，画面是一个电视首页菜单，有 10 张带程序化"印花"的 3D 卡片、会随选中项变化的模糊背景、键盘和鼠标导航。

做这件事有两个目的：

1. **练手**：React、three.js、手写 GLSL 着色器、动效和交互状态机。
2. **作品集**：成品要拿得出手，代码是自己写的。

之后可能把内容换成别的主题，所以内容必须是配置驱动的。

全部代码由实现者写完。用户通过成品、代码和学习笔记来了解每个效果，这不是一个留练习给用户的教学项目。

成功的样子：1440×900 窗口下和原站并排，肉眼看不出明显差别；交互行为一致；推到 `main` 自动上线。

## 2. 目标、非目标、反目标

### 目标

1. **视觉还原**：背景、卡片、倒影、文字排版、颗粒，并排对比肉眼看不出明显差别。
2. **交互还原**：键盘和鼠标的全部行为与原站一致（见 4.5）。
3. **配置驱动**：应用列表、输入源、每张卡片的印花参数全部来自一个配置文件，换内容不改代码。
4. **流畅**：普通笔记本 1080p 下稳定 60fps，印花纹理只生成一次。
5. **学习笔记**：五篇中文说明，讲清每个效果的原理和参数。
6. **自动部署**：推 `main` 自动发布到 GitHub Pages。

### 非目标

- 像素级一致（噪声种子、字体渲染引擎不同，做不到）。
- 移动端专门布局（和原站一样等比缩放留黑边）。
- 应用"打开"后的页面、后端、账号、真实视频源。
- 真 3D 模型、使用 Rive。
- 触摸手势、遥控器或手柄、音效、无障碍朗读优化、减少动效模式。
- 开源协议：暂不加 LICENSE，以后由用户决定。

### 反目标（即使能跑也算失败）

- 逐行翻译原作者的着色器代码。原作源码只用来理解用了什么技术。
- 把原站的资源（`.riv`、原站截图、从中抽出的源码）提交进公开仓库。
- 内容写死在组件或着色器里。
- 文字画在画布上导致发虚。
- 运行时依赖外部 CDN（字体、库都要打进产物）。

## 4. 复刻对象的完整描述

以下全部是对原站的实测结果。**如果这里的描述和原站实际行为有出入，以原站为准**，实现者自己实测补齐。故意偏离原站的地方只有第 5 节列出的那些。

### 4.1 舞台

- 逻辑舞台是 16:9（按 1920×1080 设计）。任何窗口尺寸下都等比缩放、居中，舞台外露出 `#07090c` 底色。
- 例：1440×900 的窗口里，舞台是 1440×810，上下各留 45px 黑边。手机竖屏下舞台只是中间一条。

### 4.2 画面元素

位置和字号由实现者从参考截图测量，这里只描述有什么。

- **左上**：时钟，格式 `h:mm`（12 小时制，无前导零，无 AM/PM），Inter 字体。下面一行日期，格式 `WEEKDAY, MONTH DD`（英文、全大写、日期两位数），等宽小字加宽字距。都取浏览器本地时间，实时更新。
- **右上**：两行等宽小字，加宽字距。第一行是一个绿色圆点加 `SMARTCAST · VOL 44`，浅灰色，**静态，不随任何操作变化**。第二行是琥珀色的 `PRINT {印花名} · {配色名}`，随当前选中的应用变化（焦点移到 Inputs 行时保持最后选中的应用的值）。
- **标题区**：
  - 计数：焦点在应用行时是 `APPS n / 10`，在 Inputs 行时是 `INPUTS n / 5`。琥珀色等宽小字。
  - 大标题：Lora 衬线体，白色，很大。应用行显示应用名，Inputs 行显示输入源名。
  - 副标题：Inter。应用行显示应用的副标题，Inputs 行重复显示输入源名。
  - 提示：`Press OK to open`，Inter，暗灰。
- **应用行**：小标签 `APPS`，下面是卡片行。共 10 张，同时可见 5 张。每张卡片下方是应用名（Inter），选中的为白色，其余暗灰。
- **Inputs 行**：小标签 `INPUTS`，下面 5 个圆角半透明方块：`SMARTCAST`（名字上方有一个极小的 `CAST` 标签）、`HDMI-1`、`HDMI-2`、`COMP`、`TV`。被选中的方块有一圈明亮的白色描边和轻微外发光。
- **底部提示**：`ARROWS MOVE · OK OPENS · BACK GOES UP`，等宽极小字，暗灰。
- **全屏胶片颗粒**叠在最上层。

### 4.4 四个视觉效果

这里描述的是技术和构成，不是代码。

**a. 印花（每个应用一张，离屏渲染成纹理，生成一次后复用）**

参数：四个颜色（底色、中间色、高亮色、图案色）、图案类型、种子、图案单元密度、墨渍强度。

1. 多层值噪声（fbm）加两个正弦扰动，得到一个标量场。
2. 用两个很窄的阈值把画面切成三块色域：底色、中间色、高亮色，边界近似硬边，形状像不规则的色块或地图。
3. 在中间色域里叠加图案色的重复图案。图案有五种：圆点、加号、鳞片（错位排列的半圆弧）、竖条、方块。圆点和加号的大小被另一层噪声调制，所以疏密有变化。
4. 在高亮色域里叠加另一种图案（和主图案互补的类型），更密、更淡、用底色。
5. 另一层噪声做阈值，得到零星的"墨渍"斑块，颜色是压得很暗的底色。
6. 高频噪声做轻微的纸纹明暗。

**b. 背景（全屏）**

输入：旧印花纹理、新印花纹理、过渡进度、方向（向左或向右）、种子、时间、光晕颜色和位置。

1. 只取印花纹理中间大约六成的区域放大铺满。采样坐标被两层缓慢漂移的噪声扭曲，形成随时间缓慢流动的"褶皱"。
2. 多抽头的简易模糊。过渡进行中模糊半径加大。
3. 过渡：水平方向的斜坡加噪声构成遮罩，一个随进度推进的阈值把新旧两张图分开，边界柔和且不规则，方向跟按键方向一致。阈值处叠一条暖白色混光晕色的亮带，亮带在过渡中段最亮。
4. 调色：部分去饱和，整体压暗约一半，左侧和下半部再压暗，给文字和卡片让位。
5. 在选中卡片的位置叠一个光晕色的径向光斑，光斑跟着选中项移动。焦点在 Inputs 行时光斑明显减弱。
6. 暗角。

**c. 卡片（透视相机下的薄板）**

- 每张卡片是一块有厚度的薄板，不是平面，所以侧面可见。
- 正面贴印花纹理（同样只取中间约六成）。边缘一圈很窄的深色倒角。
- 一道斜向的白色高光带。卡片被选中时，以及在它上面按 OK 时，高光带从一侧扫到另一侧，不到两秒扫完。
- 简单光照：一个固定方向光（左上前方），漫反射加一点高光。
- 选中时：边缘一圈光晕色描边，整体略提亮，卡片更大、更靠前、正对相机。
- 未选中：略小、略暗，带轻微的绕竖轴旋转。
- 侧面和背面是深灰，选中时带一点光晕色。
- 倒影：每张卡片下方一个镜像副本，贴图水平翻转、压暗，透明度从地面线向下快速衰减，最强处约三成。
- 焦点在 Inputs 行时，原先选中的卡片保持放大和靠前的位置，但失去描边光晕和提亮；卡片下的名字全部变暗。

**d. 颗粒（全屏叠加）**

每像素哈希噪声，以 24fps 跳变。正值轻微提亮，负值轻微压暗，强度很低。

### 4.5 交互行为

**键盘**

- `←` `→`：在当前行内移动。两端钳制，不循环。
- `↓`：从应用行进入 Inputs 行。在 Inputs 行按 `↓` 无效果。Inputs 行记住上次选中的输入源，再次进入时回到它；首次进入是第一个。
- `↑`、`Esc`、`Backspace`：从 Inputs 行回到应用行，应用的选中项保持不变。在应用行按这三个键无效果。
- `Enter`：OK。
  - 在应用行：选中卡片的高光带扫一次。背景不变，不打开任何页面。
  - 在 Inputs 行：没有可见变化。
- 页面加载后画布自动获得键盘焦点；点击页面任意位置也会把焦点交给画布。

**鼠标**

- 移到某张卡片上：选中该应用，焦点切到应用行。
- 移到某个输入源方块上：选中该输入源，焦点切到 Inputs 行。
- 点击卡片或方块：选中并触发 OK。
- 鼠标移到空白处：选中项不变。
- 滚轮：无效果。

**卡片行滚动**

卡片行有一个 5 格宽的可见窗口。窗口位置是独立的状态，不是选中序号的函数。规则是"只在必要时移动最少的距离"：

- 选中项在窗口内：窗口不动。
- 选中项超出窗口右边：窗口右移，直到选中项落在最右一格。
- 选中项超出窗口左边：窗口左移，直到选中项落在最左一格。
- 实测：从第 1 张一路向右，到第 6 张才开始滚，之后选中项一直在最右一格。从第 10 张往回走，第 9、8、7、6 张窗口不动，到第 5 张才开始往回滚，之后选中项一直在最左一格。
- 窗口不在最左时，舞台左边缘会露出前一张卡片的一部分。

**时间**

- 卡片、标题、光斑的切换很快，有缓出。
- 背景过渡慢得多，每次大约 3 秒。连续切换时背景按先后顺序排队，逐个播完，不跳过中间项。所以快速连按之后背景会落后于选中项好几步，再慢慢追上。
- 焦点在 Inputs 行内移动时背景不变。
- 准确时长和缓动曲线由实现者对原站录帧测量。

### 4.6 字体

原作内嵌三个字体，都是 OFL 协议的免费字体：

- **Lora**：大标题。
- **Inter**：时钟、副标题、提示、卡片名、输入源名。
- **JetBrains Mono**：所有全大写加宽字距的小字。

## 8. 我做的选择（不是用户的决定，可以推翻）

- 直接用 three.js，不用 react-three-fiber。少一层抽象，更利于练手。
- 一个全屏 WebGL 画布负责背景、卡片、倒影、颗粒。Inputs 方块和卡片下的名字用 DOM。
- 画布和 DOM 层共用同一个 16:9 舞台容器，统一缩放。
- 导航状态机是纯函数模块，不依赖 React 和 three.js。
- 内容配置是一个 TypeScript 文件。
- 工具链：pnpm、ESLint、Prettier、Vitest、Playwright。
- Vite 的 `base` 设为 `/Tv-menu/`。
- 字体只打包用到的字重，格式 woff2。
- 设计文档先放在 `docs/design` 分支，确认后合入 `main`。
- 把"练手"理解为全部代码由实现者写，用户不亲手写其中的部分。

## 10. 待用户决定

**印花的色块形状要不要和原站一样。** "并排肉眼看不出差别"和"着色器自己写"在这一点上互相冲突：色块的具体形状完全由原作的噪声公式、常数和每张卡的种子决定。

- **方案 A（推荐）：风格一致。** 配色、图案类型、三块色域的比例、质感和原站一致，色块的具体形状不同，像同一系列的另一张印花。背景是印花放大而来，所以背景的色块形状也会不同。着色器完全自己写。
- **方案 B：形状也一致。** 需要沿用原作的噪声公式和常数，并反推每张卡的种子。这等于照抄核心着色器，违反反目标第一条。

附带一个小问题：原作着色器里的通用数值（纹理裁切比例、光照方向、阈值这类）能不能直接当调参的起点。推荐可以，代码结构自己写，数值在调试中再按观感调整。
